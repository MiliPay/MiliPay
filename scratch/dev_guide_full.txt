3. STEP 1 — Backend & Database Setup
3.1 Firebase Project Setup
The very first thing your team does is create a Firebase project and enable the required services.

Action

4. STEP 2 — Authentication System
Your login system is different from standard Firebase Auth. You use phone number + system-generated password, not email/Google login.
4.1 Three Firebase Functions to Build

Function 1 — Send Password to New User
Trigger:  Agent submits registration form
Action 1: Generate a random 10-character alphanumeric password
Action 2: Hash it using bcrypt and save hash to Firestore
Action 3: Send plain password to user via SMS (use Termii for Nigerian SMS)
Action 4: Send plain password to user via email (Firebase Email Extension)

Function 2 — Login
Input:    Phone number + password from app
Action 1: Find user in Firestore by phone number
Action 2: Compare password with stored bcrypt hash
Action 3: If match — generate Firebase Auth custom token
Action 4: Return token to app
Action 5: App uses token to authenticate all future requests

Function 3 — Create PIN (First Login Only)
Input:    User's chosen 4 or 5 digit PIN
Action 1: Hash the PIN using bcrypt
Action 2: Save hash to user's Firestore document
Action 3: NEVER store the plain PIN anywhere
Action 4: Confirm PIN saved — allow full app access

Security Rule
The PIN is hashed immediately and the plain version is discarded. It is never transmitted or stored anywhere. Only the user knows their PIN.


5. STEP 3 — Agent Registration Portal
Your registration agents need a web portal to register users. Build this as a React web app — same skills as React Native.
5.1 Agent Portal Flow

Agent logs into secure web portal with their own credentials
Agent fills registration form: Full name, Phone number, Email, BVN, NIN
Agent captures fingerprint using USB fingerprint scanner connected to their computer
Portal converts fingerprint image to encrypted template before sending to Firebase
Firebase Function creates user record in Firestore
System sends password to new user within 24 hours via SMS and email
Agent sees success confirmation on screen

5.2 Fingerprint Scanner Hardware for Agents
Device
Use a USB fingerprint scanner at each agent station. Recommended brands available in Nigeria: Nitgen or Futronic. Cost: approximately N15,000 to N30,000 per device.

6. STEP 4 — Bank Account Linking (Mono)
This is how users link their bank accounts inside the React Native app using the Mono API.
6.1 Setup

Create a developer account at mono.co
Get your sandbox public key and secret key from the Mono dashboard
Install the Mono React Native SDK: npm install react-native-mono-connect

6.2 Account Linking Code Flow
// React Native — Account Linking
import MonoConnect from 'react-native-mono-connect';

const config = {
  key: 'your_mono_sandbox_public_key',
  onSuccess: (data) => {
    // data.code returned after user links account
    // Send this code to your Firebase Function
    linkAccountToUser(data.code);
  },
  onClose: () => console.log('Widget closed')
};

// Render when user taps 'Link Bank Account'
<MonoConnect config={config} />

6.3 Firebase Function — Exchange Mono Code for Account Token
Receive the Mono code sent from the app
Call Mono API with the code — Mono returns permanent account ID and account details
Save bank name, account name, encrypted account number, and Mono account ID to Firestore
Confirm success back to the app
App displays the newly linked bank in the accounts list
This process repeats up to 5 times for different accounts


7. STEP 5 — Payment Processing (Flutterwave)
7.1 Setup

Create a developer account at flutterwave.com
Get your sandbox public key and secret key
CRITICAL: Secret key goes ONLY in Firebase Functions — NEVER in the mobile app

7.2 Payment Flow — Step by Step
User's fingerprint is scanned at terminal — system identifies user
App retrieves user's linked accounts from Firestore and displays them
User selects which bank account to pay from
User enters their PIN
App sends: amount, selected account ID, merchant ID, and user ID to Firebase Function
Firebase Function verifies PIN hash matches stored hash
Firebase Function calls Flutterwave API to initiate the debit
Flutterwave processes payment and debits user's bank account
Firebase Function saves transaction record to Firestore
Success confirmation returned to app and merchant terminal simulation

7.3 Firebase Function — Payment Code Flow
// Firebase Function — Process Payment
exports.processPayment = functions.https.onCall(async (data, context) => {
  const { amount, accountId, merchantId, pin } = data;
  const userId = context.auth.uid;

  // Step 1: Verify PIN
  const user = await db.collection('users').doc(userId).get();
  const pinMatch = await bcrypt.compare(pin, user.data().pinHash);
  if (!pinMatch) throw new Error('Invalid PIN');

  // Step 2: Get linked account details
  const account = await db.collection('users').doc(userId)
    .collection('linkedAccounts').doc(accountId).get();

  // Step 3: Call Flutterwave API
  const response = await flutterwave.charge({
    amount,
    account_bank: account.data().bankCode,
    account_number: decrypt(account.data().accountNumber),
    currency: 'NGN',
    tx_ref: generateReference(),
  });

  // Step 4: Save transaction
  await db.collection('transactions').add({
    userId, merchantId, amount,
    status: response.status,
    reference: response.data.tx_ref,
    timestamp: admin.firestore.FieldValue.serverTimestamp()
  });

  return { success: true, reference: response.data.tx_ref };
});

8. STEP 6 — Biometric Simulation (Prototype)
For the prototype, use the phone's built-in fingerprint scanner to simulate the POS terminal biometric scan. This will be replaced by the custom hardware terminal in the full product.

// React Native — Phone Fingerprint for Prototype
// npm install react-native-biometrics

import ReactNativeBiometrics from 'react-native-biometrics';

const rnBiometrics = new ReactNativeBiometrics();

// Call this when user initiates payment
const authenticateUser = async () => {
  const { success } = await rnBiometrics.simplePrompt({
    promptMessage: 'Confirm payment with fingerprint',
    cancelButtonText: 'Cancel'
  });

  if (success) {
    // Fingerprint confirmed — proceed to account selection
    navigation.navigate('SelectAccount');
  } else {
    Alert.alert('Authentication failed', 'Please try again');
  }
};

Note
This phone fingerprint step replaces the physical POS terminal scan for prototype purposes only. The real product will use a fingerprint sensor built into the custom POS terminal hardware.

9.1 What the Merchant Screen Shows

STATE
WHAT IS DISPLAYED

Payment failed

9.2 How Merchant Gets Real-Time Updates
Use Firebase Firestore real-time listener on the merchant screen. When a transaction document is created in Firestore, the merchant screen updates instantly without refreshing.

// Merchant Screen — Real-Time Payment Listener
useEffect(() => {
  const unsubscribe = firestore()
    .collection('transactions')
    .where('merchantId', '==', merchantId)
    .where('status', '==', 'success')
    .orderBy('timestamp', 'desc')
    .limit(1)
    .onSnapshot(snapshot => {
      if (!snapshot.empty) {
        const latest = snapshot.docs[0].data();
        setPaymentStatus('success');
        setTransactionDetails(latest);
      }
    });

  return () => unsubscribe(); // Clean up listener
}, [merchantId]);

12. Critical Rules for Your Development Team

NEVER put Flutterwave secret key or Mono secret key inside the React Native app code — only in Firebase Functions
NEVER store plain text PINs anywhere — always hash with bcrypt before saving
NEVER store raw fingerprint images — only encrypted processed templates
ALWAYS use HTTPS for all API calls — never plain HTTP
ALWAYS validate inputs on the Firebase Function side — never trust data from the app alone
ALWAYS test failure cases — not just the happy path
NEVER go live with sandbox API keys — switch to live keys only when legal requirements are complete

This document is confidential and intended for the development team only. All API keys must be stored securely and never committed to version control.
